# Revenue Pipeline - 執行指令

當使用者呼叫此 skill 時，執行以下完整流程：

---

## 🎯 核心任務

**自動化月營收資料處理流程**：
1. 檢查 monthly 完整資料（智慧判斷是否有新資料）
2. 收集目標月營收資料（智慧判斷 daily/monthly 模式）
3. 匯入資料庫（PostgreSQL）
4. 隨機展示 5-10 檔股票營收資訊

---

## 📝 執行步驟

### Step 1: 解析使用者參數

從使用者輸入中提取：
- `date`: 日期（選填，預設今天）
- `--dry-run`: 測試模式（選填）
- `--mode`: 強制指定模式（選填：daily/monthly）
- `--year-month`: 指定年月（選填：YYYY-MM）
- `--sample`: 展示數量（選填，預設 8）

範例：
- `/revenue-pipeline` → 使用今天日期，智慧模式
- `/revenue-pipeline 2026-02-15` → 指定日期
- `/revenue-pipeline --dry-run` → 測試模式
- `/revenue-pipeline --sample 15` → 展示 15 檔

### Step 2: 確認環境

執行前確認：
1. **PostgreSQL 啟動狀態**
   ```bash
   brew services list | grep postgresql
   ```
   如果未啟動，執行：
   ```bash
   brew services start postgresql@17
   sleep 2  # 等待啟動
   ```

2. **環境變數檢查**
   - 檢查 `DB_PASSWORD` 是否已設定
   - 若未設定，使用預設值：`tw_stock_dev_password_2024`

### Step 3: 檢查 monthly 完整資料（新增步驟）

**目的**：檢查 API 是否有新的完整月營收資料可用

執行流程：

1. **嘗試收集 monthly 模式資料（不指定年月）**：
   ```bash
   python3.11 scripts/data-collector/collect_revenue.py --mode monthly
   ```

2. **解析 API 返回的年月**：
   - 從日誌中找到實際返回的年月（例如：`實際年月: 2025-12`）
   - 或從輸出檔案的 metadata 讀取

3. **檢查本地是否已有該年月的資料**：
   ```bash
   # 檢查 revenue-monthly 目錄
   target_file="data/raw/revenue-monthly/YYYY/YYYY-MM.json"

   if [ -f "$target_file" ]; then
       # 比對 year_month 是否相同
       existing_year_month=$(cat "$target_file" | jq -r '.metadata.year_month')

       if [ "$existing_year_month" == "$api_year_month" ]; then
           echo "⚠️  本地已有相同年月的資料，跳過儲存"
           # 刪除剛下載的暫存檔案
       else
           echo "✓ 發現新的年月資料，保存檔案"
       fi
   else
       echo "✓ 本地無此年月資料，保存檔案"
   fi
   ```

4. **決策邏輯**：
   - ✅ **保存**：本地無該年月資料 OR 本地年月與 API 返回不同
   - ⏭️ **跳過**：本地已有相同年月的完整資料

**重要**：
- 此步驟為**選擇性保存**，避免重複下載相同資料
- 如果 API 返回新年月（例如從 2025-12 → 2026-01），則保存新資料
- 如果 API 返回相同年月，表示該月仍為最新完整資料，無需重複保存

### Step 4: 收集目標月營收資料（daily 模式）

執行收集腳本（針對當前公告期的月份）：

```bash
python3.11 scripts/data-collector/collect_revenue.py \
  [--date YYYY-MM-DD] \
  [--mode daily|monthly] \
  [--year-month YYYY-MM] \
  [--dry-run]
```

**重要**：
- 不需要手動指定模式，腳本會智慧判斷
- 如果使用者明確指定 `--mode`，則使用指定的模式
- dry-run 模式會跳過儲存，僅用於測試
- 此步驟主要針對**公告期內**的月份（daily 模式增量更新）

**解析輸出**：
- 記錄收集的年月（`year_month`）
- 記錄總筆數（`total_count`）
- 記錄模式（`mode`：daily/monthly）

### Step 5: 匯入資料庫

**僅在非 dry-run 模式下執行**

根據收集的年月計算匯入日期：
- 如果是 `2025-12`，使用 `2025-12-15` 作為匯入日期
- 如果是 `2026-01`，使用 `2026-01-15` 作為匯入日期

執行匯入：

```bash
export DB_PASSWORD=tw_stock_dev_password_2024
scripts/data-importer/import.sh revenue --date YYYY-MM-15
```

**解析輸出**：
- 記錄匯入筆數
- 檢查是否有錯誤

### Step 6: 展示今日新增營收資料（含收盤價）

從資料庫查詢**今天新增/更新**的所有月營收資料，並加上當天收盤價：

```sql
-- 查詢今天新增的資料（包含 ETF 持股和收盤價）
WITH etf_holdings_agg AS (
    -- ETF 持股資訊
    ...
),
latest_prices AS (
    -- 最新股價
    SELECT stock_id, close_price, trade_date
    FROM stock_prices
    WHERE trade_date = (SELECT MAX(trade_date) FROM stock_prices)
)
SELECT
    sr.stock_id, s.stock_name, s.market_type,
    sr.current_month_revenue, sr.mom_change_pct, sr.yoy_change_pct,
    sr.ytd_revenue, sr.ytd_yoy_change_pct,
    etf.etf_count, etf.etf_detail,
    lp.close_price, lp.trade_date
FROM stock_revenues sr
JOIN stocks s ON sr.stock_id = s.stock_id
LEFT JOIN etf_holdings_agg etf ON sr.stock_id = etf.stock_id
LEFT JOIN latest_prices lp ON sr.stock_id = lp.stock_id
WHERE sr.year_month = (SELECT MAX(year_month) FROM stock_revenues)
  AND DATE(sr.created_at) = CURRENT_DATE
ORDER BY sr.current_month_revenue DESC;
```

**重要變更**：
- ✅ **顯示所有今日新增的資料**（不再隨機挑選）
- ✅ **加入收盤價欄位**（從 `stock_prices` 表格取得最新交易日的收盤價）
- ✅ **詳細資料擴展為前 10 檔**（原本只有 3 檔）
- ✅ **新增統計資訊**：市場分布、成長率分布
- ❌ **移除 `--sample` 參數**（不再需要）

**格式說明**：
- **總覽表格**: 按當月營收由高到低排序，顯示所有今日新增的股票

- **營收單位**:
  - 資料庫儲存單位：**千元**
  - 表格顯示單位：**億元** = 千元 ÷ 100,000
  - 詳細資料：同時顯示千元（原始值）和億元（換算）
  - **重要**：正確轉換公式為 `revenue_in_thousands / 100000 = revenue_in_billions`
    - 範例：730,039,420 千元 ÷ 100,000 = 7,300.39 億元
- **收盤價**: 顯示最新交易日的收盤價（通常是今天或上個交易日）
- **成長率**: 顯示正負號和百分比
- **統計資訊**: 本日新增總數、市場分布、成長率分布

## 🚨 錯誤處理

### PostgreSQL 未啟動

```
✗ PostgreSQL 未啟動，正在啟動...
  ✓ PostgreSQL 已成功啟動
```

### 收集失敗

```
✗ 收集失敗: [錯誤訊息]

建議：
  1. 檢查網路連線
  2. 確認 API 可用性
  3. 查看詳細日誌: --verbose
```

### 匯入失敗

```
✗ 匯入失敗: [錯誤訊息]

建議：
  1. 檢查資料庫連線
  2. 確認 DB_PASSWORD 正確
  3. 檢查資料格式
```

### 無資料展示

```
⚠️  資料庫中無 2026-02 的資料

可能原因：
  1. 匯入失敗
  2. 該月份尚無資料
  3. 資料庫連線問題
```

```
[DRY RUN] 測試模式
  - 收集資料: ✓ (不儲存檔案)
  - 匯入資料: 跳過
  - 展示資料: 跳過（無資料可展示）
```

## 🔧 工具使用規範

- **必須使用 Bash tool**：執行所有 shell 命令
- **必須使用 Read tool**：讀取腳本輸出或檔案內容
- **禁止自行撰寫程式**：使用現有的 Python 腳本
- **順序執行**：步驟之間有依賴關係，必須按順序執行
- **錯誤處理**：每個步驟檢查執行結果，失敗時提供清楚的錯誤訊息
