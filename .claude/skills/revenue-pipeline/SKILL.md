# Revenue Pipeline Skill

**一鍵執行月營收資料處理流程**：收集 → 匯入 → 展示

---

## 🎯 功能說明

此 skill 自動化處理月營收資料的完整流程：

1. **檢查完整資料**：先嘗試取得 monthly 最新完整資料，若本地已有相同年月則跳過
2. **智慧收集**：根據日期自動判斷使用 daily 或 monthly 模式收集目標月份
3. **資料匯入**：將 JSON 資料匯入 PostgreSQL 資料庫
4. **隨機展示**：隨機挑選 5-10 檔股票展示營收數據

---

## 📋 使用方式

### 基本用法

```bash
# 自動處理（智慧判斷模式）
/revenue-pipeline

# 指定日期處理
/revenue-pipeline 2026-02-15

# 測試模式（不實際儲存）
/revenue-pipeline --dry-run
```

---

## 🔄 執行流程

```
1. 檢查 monthly 完整資料
   ├─ 嘗試取得最新完整月份（monthly 模式）
   ├─ 比對本地是否已有相同年月
   ├─ 相同 → 跳過儲存（避免重複下載）
   └─ 不同 → 保存新資料

2. 智慧判斷目標月份模式
   ├─ 10號前 → daily 模式（漸進式收集當月公告）
   └─ 10號後 → monthly 模式（完整收集當月）
         └─ 若 API 返回不符 → 自動切換 daily

3. 收集目標月營收資料
   ├─ daily: 增量更新，查詢未公告股票
   └─ monthly: 一次取得所有完整資料

4. 匯入資料庫
   └─ 寫入 stock_revenues 表

5. 隨機展示
   └─ 從資料庫隨機挑選 5-10 檔展示
```

## 💡 使用案例

### 每月 10 日前：漸進式追蹤

```bash
# 每天執行，自動累積已公告的股票
/revenue-pipeline
```

每次執行只查詢未公告的股票，節省時間。

```bash
# 一次收集所有完整資料
/revenue-pipeline
```

## ⚠️ 注意事項

1. **資料庫連線**：執行前確保 PostgreSQL 已啟動
2. **密碼設定**：必須設定 `DB_PASSWORD` 環境變數
3. **API 限制**：daily 模式每次查詢間隔 0.3 秒（約 10 分鐘）
4. **資料覆蓋**：匯入時會覆蓋相同 (year_month, stock_id) 的舊資料

---

## 🐛 常見問題

**Q: 為什麼 monthly 模式還會切換成 daily？**
A: 當 API 返回的年月與預期不符（如請求 2026-02 但返回 2025-12），系統會自動降級為 daily 模式收集當月部分公告的資料。

**Q: 資料會重複嗎？**
A: 不會。資料庫有 UNIQUE 約束 (year_month, stock_id)，相同資料會被覆蓋更新。

**Q: daily 模式為什麼這麼慢？**
A: daily 模式需逐一查詢每檔股票是否公告，為避免被 API 封鎖，每次查詢間隔 0.3 秒。建議在 10 號後改用 monthly 模式。
