## 🎯 使用案例

### 案例 1: 每月初追蹤

**情境**：每月 1-10 日，追蹤已公告公司

```bash
# 每天執行
/revenue-pipeline
```

**效果**：
- 自動使用 daily 模式
- 只查詢未公告的股票
- 增量更新，節省時間

### 案例 2: 月中完整收集

**情境**：每月 10 日後，收集完整資料

```bash
# 一次執行
/revenue-pipeline
```

**效果**：
- 自動使用 monthly 模式
- 一次取得所有資料
- 快速完整

### 案例 3: 補齊歷史資料

**情境**：補齊過去月份的資料

```bash
# 指定年月
/revenue-pipeline --year-month 2025-12 --mode monthly
```

## 🔧 進階選項

### 參數說明

| 參數 | 說明 | 範例 |
|------|------|------|
| `--date` | 指定日期 | `--date 2026-02-15` |
| `--mode` | 強制模式 | `--mode daily` 或 `--mode monthly` |
| `--year-month` | 指定年月 | `--year-month 2026-01` |
| `--sample` | 展示數量 | `--sample 15` |
| `--dry-run` | 測試模式 | `--dry-run` |

### 組合使用

```bash
# 測試收集 2026-01，展示 15 檔
/revenue-pipeline --year-month 2026-01 --sample 15 --dry-run

# 強制使用 monthly 模式
/revenue-pipeline --mode monthly --date 2026-02-15
```

## 🐛 故障排除

### PostgreSQL 未啟動

**錯誤**：
```
✗ PostgreSQL 未啟動
```

**解決**：
```bash
brew services start postgresql@17
```

### DB_PASSWORD 未設定

**錯誤**：
```
⚠️  DB_PASSWORD 環境變數未設定
```

**解決**：
```bash
export DB_PASSWORD=tw_stock_dev_password_2024
```

### 資料收集失敗

**錯誤**：
```
✗ 收集失敗: [錯誤訊息]
```

**解決**：
1. 檢查網路連線
2. 確認 API 可用性
3. 查看詳細日誌：`--verbose`

## 💡 提示

1. **最佳執行時間**：
   - 1-10 日：每天執行（追蹤新公告）
   - 10 日後：一次執行（完整資料）

2. **資料覆蓋**：
   - 匯入時會自動覆蓋相同 (year_month, stock_id) 的舊資料
   - 不需要手動刪除舊資料

3. **效能優化**：
   - daily 模式會自動跳過已公告的股票
   - monthly 模式速度快，建議 10 日後使用
